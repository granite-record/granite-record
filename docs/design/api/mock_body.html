The Data API

The whole record behind this site, as files a program can read: every bill of every term with its full history, every roll call and every member’s vote, and one list joining every number the General Court uses for a person. No key, no account and no limit to ask about: they are plain files, rebuilt every night.

A beta until February 1, 2027. Until then a file or a field may still change, and every change is listed below. From then on, changes only add things.

The Files

Everything is under /data/, beside the spreadsheets on the data page, and data/manifest.json lists every file with its address, size and the night it was built. Start there: one request says what is here and how much. The bill files are compressed with gzip and the database with xz, which Python, R and the command line on Linux and macOS open with what they already have.

Getting Started

Every bill of the current term, in Python, with nothing to install:

import gzip, json, urllib.request
url = "https://graniterecord.org/data/bills-2025-2026.jsonl.gz"
with urllib.request.urlopen(url) as r, gzip.open(r) as lines:
    for line in lines:
        bill = json.loads(line)
        print(bill["key"], bill["title"])

Or the whole database, opened in the sqlite3 program:

curl -O https://graniterecord.org/data/granite-record.sqlite.xz
xz -d granite-record.sqlite.xz
sqlite3 granite-record.sqlite "SELECT term, COUNT(*) FROM bills GROUP BY term"

A page on another site may read every file here from the reader’s browser too: each one is served to any origin.

Keys and Joins

A bill is its term and its number. HB 100 names a different bill in every term, so every file writes a bill as 2025-2026/HB1442, or as a term and a bill column side by side.

A person is a person. The General Court numbers a member in two ways, an employee number and a person id, and this site’s files use both; one person can carry several of each. people.json joins them to one person, which does not change when a member moves from the House to the Senate.

When two entries prove to be one person, or one is two

A person is never given to anyone else. If two entries prove to be one person, the one that goes stays in the file with a replaced_by line, so a program that stored it can still find them. If one entry proves to be two people, it keeps its number and the other gets a new one, marked split_from. A new member’s number is marked provisional until it is issued.

A blank field is usually an answer

The record leaves it empty, the document that would fill it has not been collected, or this site does not read it yet. The data page’s coverage table counts how far each column reaches in each term.

What Changed Tonight

/changes/<date>.json is what each night’s build found new, kept for the last eight nights. It already lists the hearings, votes and actions each bill, member, committee and topic gained. It now also lists every bill and person whose record changed, in any term. With the checksums in manifest.json, another site can fetch only what moved.

Today’s Votes

On a day the House or the Senate sits, /api/live/votes/<date> holds the roll calls recorded so far that day. The nightly files above take the day in the next morning.

What is live on the General Court’s video streams is not part of the API. Each bill’s page links its recording.

What It Covers

The General Court publishes its record as a database. Every table of it this site reads lands somewhere here, and manifest.json lists each one with where it goes. A few do not, each for a reason:

What is not here, and why

The names of people who sign in to testify. Only the counts for and against each hearing are published; names, towns and written testimony are never collected. Four tables nothing reads: the hearing view, two lists of codes, and a table of past districts. The statutes’ text, which is on the laws pages rather than here.

What comes from outside the database

The House and Senate calendars, for the House committee reports and their reasoning, interim study statements and every noticed meeting. The times within each recording are this site’s own.

Versions and Stability

Every JSON file carries "format": 1. Until February 1, 2027 the API is a beta, and a field may be renamed or removed; each such change is listed here and in manifest.json a week before it happens. From February 1, changes only add: a new file, a new field, a new column at the end. A change that cannot be made by adding becomes a new file beside the old one, and both are published for a year.

Using It

The record is the State of New Hampshire’s and is public. What this site adds — its ids, its joins, its corrections and its timings — is dedicated to the public domain: use it for anything, with no need to ask. The code that builds it is MIT licensed. A link back to graniterecord.org helps somebody check your working.

Found something that looks wrong, or a shape that is awkward to use? Each bill’s page has a Report a problem button, or write to contact@graniterecord.org.
